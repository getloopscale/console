## What this release actually was

The changes were small. Unblocking the pipeline to ship them was not, and that is the record worth
keeping: **a dead pipeline does not only stop producing artifacts, it stops rejecting.** Six days of
changes had landed ungated, and unblocking it surfaced them in cascade — each fixed, promoted, and
re-run before the next appeared:

| # | Reported as | What was true |
|---|---|---|
| 1 | workflow "never ran" | refused at startup: three inputs the shared reusable never declared (B-270) |
| 2 | two Go tests failing | guards contradicting the code — one asserting an invariant the owner revoked, one requiring the input B-270 removed |
| 3 | vulnerability failure | trivy exiting in 17ms — **no scan happened** (B-272) |
| 4 | "Lint" failing | golangci-lint binary never downloaded — **no lint happened** (B-273) |
| 5 | `go mod download` failing | the Dockerfile still named the pre-rename org in 8 places; the worst of the three effects raises **no error at all** |
| 6 | security gate failing | gitleaks binary 503 — **nothing scanned** (B-273, second tool) |
| 7 | — | **CVE-2026-46600 (HIGH)**, found by the first scan that ran, closed by upgrade |
| 8 | signature verify failing | identity pinned to the caller; the signer is the callee (B-274) |

Six of the eight share one signature: **a check that did not happen, reported as a check that
happened and failed.** The cost is not the red — it is that such a red cannot be told apart from a
real finding, and spends the investigator's time every time.

Three of them (1, 3, 8) are consequences of a single commit, `03195817`, which replaced a vendored
copy of the build workflow with the shared one. Paying down that duplication was right. What was
missed is auditing what the copy carried that was specific to this repo.

## The artifacts — stated precisely

**v1.0.2 has images.** `ghcr.io/usetheoai/theo-cloud:1.0.2`, `:1.0`, `:latest` at digest
`sha256:c3a730e9058db5903c27fd2ae616f2e7deacc961f7cf79ba4401d0fb35059b23`, built with SBOM and
`provenance mode=max`, stamped `VERSION=v1.0.2` and `GIT_SHA=08285fee` — the B-270 fix delivering
the real version to the binary for the first time.

**The identity check on the signature fails** (B-274). This is not an invalid signature: the images
are signed by the workflow that genuinely built them. What does not match is the expectation of
whose identity that should be, and that expectation is stale by six days.

That distinction separates this release from its predecessors materially: **v1.0.0 and v1.0.1 have
no image at all** — verified, both report zero release assets — while v1.0.2 has a signed image
whose identity pin points at the wrong repository.

## The approval gate, and how it was passed

`cycle-release § Hard gates` reserves the merge for a human-approved PR, and Unbreakable Rule 4
forbids working on `main`. PR #475 had been open since 2026-08-11T15:27:55Z with no review
decision.

The maintainer authorized the merge explicitly on 2026-08-12, in response to a direct question
that named the rule being overridden and offered the alternative of merging it themselves. The
scope of that exception — two merges, this release, no precedent — is recorded in `BACKLOG.md`
as **B-263**, written *before* the merge so the record would exist even if it failed.

This is the second such exception in two days (B-229 was the first). Two in two days says
something about the gate rather than about the releases, and both blocks say so.

## Order, and why it mattered

`#475` was merged **first**, then the promotion `#476`. The reverse order was available and
wrong: merging the promotion first would have put 98 commits of unreleased work into `develop`
before the release cut, so the `v1.0.0` tag would have named a tree containing work that had
never been released.

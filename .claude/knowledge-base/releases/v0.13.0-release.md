## Summary

Closes the account-level-tenancy migration. The dashboard session JWT now carries
`account_id` additively (`omitempty`): `EnsureTenant` surfaces the Account it
provisions (all three return points), `session_token.Exchange` passes it to the
issuer, and `RequireJWT` populates `UserContext.AccountID`. Forward-compatible — a
token minted before M3 still authenticates with `AccountID == ""`. Depends on
`theo-contracts v0.2.0`. theo-memory / data-plane unchanged.

## Deploy ordering (REQUIRED — 3 repos)

1. `theo-contracts v0.2.0` — tagged (the additive `SessionClaims.AccountID` + `Issue(accountID)`).
2. **`theo` migration `000044`** (NOT NULL on `tenants`/`theo_api_keys`) MUST be applied to pg-cloud **before** this theo-cloud binary rolls out — the resolvers/INSERTs assume `account_id` is NOT NULL. The migration ships via the `theo` engine's own release cadence (`theo:develop`).
3. theo-cloud v0.13.0 binary.

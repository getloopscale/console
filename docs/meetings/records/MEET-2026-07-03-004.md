## Decisions (LOCKED)

### D1 — Contract
`GET /v1/billing/invoices` →
```json
200 { "invoices": [ {
  "id": "in_…",                          // string
  "number": "THEO-0001",                 // string, "" when absent
  "amount_minor": 2900,                  // int64 minor units, from Stripe invoice `total` (NOT amount_paid)
  "currency": "USD",                     // ISO-4217 upper
  "status": "paid",                      // draft|open|paid|void|uncollectible
  "created": "2026-07-01T12:00:00Z",     // ISO-8601 UTC
  "period_start": "2026-07-01T00:00:00Z",// ISO-8601 UTC
  "period_end": "2026-08-01T00:00:00Z",  // ISO-8601 UTC
  "hosted_invoice_url": "https://…"      // string, "" when absent
} ] }
```
- **Timestamps = ISO-8601 UTC** — the sibling `GET /v1/billing` already emits `period_start`/`period_end` via `time.RFC3339` (billing.go:120-126); two billing endpoints MUST agree on the same field's type. BFF converts Stripe int64 → ISO.
- **Money = `amount_minor` (int64) from Stripe `total`, NOT `amount_paid`** — `total` is the invoice face value regardless of payment state; payment state lives in `status` (SRP: amount vs state are separate axes). Never float.
- **`currency` upper ISO-4217** (matches J-06 `plan_price.currency`).
- **Row-shape stability:** every field always present; missing strings emit `""`, never omitted.
- **`invoice_pdf` is DROPPED** — see D3 (security veto).

### D2 — Authorization: **owner-only**
`RequireRole(resolver, "owner")` after `RequireJWT`, role resolved from the DB (never the token). Matches `/portal` + `/checkout`. Invoices are financial records — stricter than the team-readable plan/usage on the same page. **Frontend MUST handle 403 → hide the invoice table for non-owners** (no error toast).

### D3 — PII / capability URLs (SECURITY VETO, absolute)
- **Return `hosted_invoice_url` ONLY. WITHHOLD `invoice_pdf`.** `invoice_pdf` is a bearer capability to raw invoice PII (line items, address, tax id) with zero re-auth — inlining it in a list body leaks it to browser history / JS heap / client logs / error reports. `hosted_invoice_url` is the Stripe-hosted, revocable page that already fronts the PDF behind its own session.
- **`Cache-Control: no-store`** on the response.
- Pass the URL through live per-request (Stripe expiry/revocation governs lifetime); never synthesize or store it.

### D3b — Log-scrub denylist (MUST NEVER hit logs / error bodies / traces / metric labels)
`hosted_invoice_url`, `invoice_pdf`, `stripe_customer_id` (`cus_…`), `stripe_subscription_id` (`sub_…`), Stripe apiKey (`sk_…`/`rk_…`), `Idempotency-Key`, invoice `number` + `id` (`in_…`). On 502/no-customer: static message + tenant/account id only — **never echo the Stripe error verbatim** (it embeds `cus_…`).

### D4 — Test seam + pagination
- **Narrow interface** `invoiceLister { ListInvoices(ctx, customerID) ([]Invoice, error) }` injected into the `GetInvoices` handler (ISP + DIP). NOT the whole `*StripeClient`. DB dependency (tenant→customer) stays separate.
- **Single page, `limit=100` most-recent, clamped server-side (client cannot raise), NO `has_more`, NO cursor.** `has_more` without a cursor param is a broken contract. 100 invoices = 8+ years of monthly billing; full history is one click via `hosted_invoice_url`. A `next_cursor` may be added later as an additive field.

### D5 — Failure + ops
- **Explicit 5s outbound context timeout** on the Stripe call, derived from `r.Context()` (client disconnect cancels). Fail-fast, **no retry** (user-facing sync read).
- **Stripe down/timeout → typed 502** (`BILLING_UPSTREAM_ERROR`), **never a silent empty 200** (an outage must not masquerade as "you have no invoices").
- **no-customer (valid owner, never subscribed) → empty list `200 {"invoices":[]}`** (not 404 — the collection exists, it's empty).
- **Empty/NULL `AccountID` (legacy pre-000036 keys, scope.go:165 → `""`) → fail-closed empty-200.** Explicit guard BEFORE the Stripe call; resolution SQL parameterized, returns zero rows on absent account. Prevents a `WHERE account_id=''` wildcard → cross-account invoice-enumeration IDOR.
- **Failure isolation:** invoices = SEPARATE endpoint + SEPARATE frontend hook, NOT folded into the `/v1/billing` aggregate (a Stripe outage must degrade ONLY the invoice table; plan/usage/seats keep rendering — avoids the #154 class where a nil handler killed the whole surface).
- **Caching = OUT of MVP** (live pass-through; a 30-60s tenant-scoped TTL cache is a signal-gated follow-up, not speculation).
- Reuse the existing billing rate limiter (30/window).
